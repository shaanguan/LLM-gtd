# 收集箱处理

## 核心原则

收集箱（Inbox）是所有输入的统一入口——想法、任务、邮件、会议笔记，全部先扔进来。处理时的铁律是：**一条条顺序处理，不跳跃、不挑选**。跳着处理会让难啃的条目永远沉底。

## 决策树

拿起一条，依次问自己：

### 第一问：这件事能付诸行动吗？

**不能行动** → 三种去向：
- **垃圾** — 不再有价值，直接删除
- **参考资料** — 有价值但不需要行动，归档到对应知识库
- **将来/也许** — 现在不做但将来可能做，移入 [[someday-maybe|将来/也许清单]]

**能行动** → 进入第二问

### 第二问：两分钟内能搞定吗？

- **能** → 立刻执行。不记录、不排期，做完就完。这是 GTD 著名的"两分钟规则"——记录它所花的时间比做完它还长，那就直接做。
- **不能** → 进入第三问

### 第三问：是我亲自做，还是交给别人？

- **委托他人** → 发出委托，然后在 [[waiting-for|等待清单]] 中记一条
- **自己做但不是现在** → 明确 [[next-action|下一步行动]]，打上 [[context-labels|情境标签]]，放入对应清单；如果该事项属于多步骤结果，确保有对应的 [[project-definition|项目]] 存在

## 处理节奏

- 理想频率：每天至少清空一次收集箱
- 每条处理时间：几秒到一两分钟（决策，不是执行）
- 目标：收集箱归零。零不是指事情都做完了，而是每条都被决策过、分流到了正确位置

## 常见陷阱

1. **把收集箱当待办清单用** — 收集箱是暂存区，不是工作区。未经处理的条目不应直接执行。
2. **一次处理太多导致疲劳** — 如果积压过多，分批处理也可以，但每批内保持顺序。
3. **过度思考** — 处理阶段只做分流决策，不做深度规划。规划留给专门的项目计划时间。
